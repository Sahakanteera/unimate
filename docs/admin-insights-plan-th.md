branch `kim` · 11 ต.ค. 2026 · สถานะ: พัฒนาและรีวิวแล้ว ยังไม่ commit

## เป้าหมาย

หน้าวิเคราะห์ข้อมูลที่เห็นได้เฉพาะแอดมิน ตอบ 4 คำถาม:

1. ระบบถูกใช้แค่ไหน (KPI 4 ตัว)
2. กิจกรรมเพิ่มหรือลดตามเวลา (กราฟแนวโน้ม)
3. กิจกรรมจัดกันวันไหน เวลาไหน (heatmap)
4. หมวดไหนได้ผลดี (สรุปแยกตามหมวดหมู่)

ทุกตัวเลขดาวน์โหลดเป็นไฟล์ CSV ไปใช้ต่อได้ (Excel / Google Sheets)

## ช่วงเวลาและนิยามตัวชี้วัด

- **ตัวกรอง (`range`):** `30d`, `90d` (ค่าเริ่มต้น), `all` ช่วงคือ `[from, now]` โดย `30d`/`90d` เริ่มเที่ยงคืนของวันที่ย้อนไป 30/90 วัน และ `all` เริ่มจากวันที่ของกิจกรรมแรก ถ้าค่าไม่ถูกต้องให้ใช้ `90d` ไม่ error
- **กิจกรรมในช่วง:** `starts_at` อยู่ใน `[from, now]` รวมกิจกรรมที่ถูกซ่อน ส่วนคำขอ การเช็กชื่อ และรีวิว นับตามกิจกรรมเหล่านี้
- **เวลา:** ทั้งหมดใช้ `Asia/Bangkok`

| KPI | สูตร |
|---|---|
| กิจกรรมที่จัด | กิจกรรมในช่วงที่ status≠cancelled บรรทัดรองบอกจำนวนที่ยกเลิกและ % |
| ผู้ใช้ที่มีส่วนร่วม | จำนวนนักศึกษาไม่ซ้ำที่เป็นผู้จัด หรือส่งคำขอเข้ากิจกรรมในช่วง (ไม่นับแอดมิน) ÷ นักศึกษาทั้งหมด |
| อัตราเติมที่นั่ง | ผู้ได้รับอนุมัติ ÷ ผลรวม capacity ของกิจกรรมที่จัด |
| อัตรามาตามนัด | present ÷ (present + absent) บรรทัดรองบอก "เช็กชื่อแล้ว N · ยังไม่เช็กชื่อ M" (อนุมัติแล้ว กิจกรรมจบแล้ว แต่ยังไม่บันทึก) |

ถ้าตัวหารเป็น 0 ให้แสดง "–" ห้ามหารด้วย 0

## โครงหน้า

1. `admin.partials.header` (แท็บ "ภาพรวมข้อมูล" เป็นแท็บแรก)
2. ตัวกรองช่วงเวลา (chip) + ปุ่ม "ดาวน์โหลด CSV" ในแถวเดียวกัน ทั้งสองอย่างมีผลกับทุกส่วนด้านล่าง
3. KPI 4 ใบ
4. กราฟแท่ง "จำนวนกิจกรรมที่จัด" (`30d` รายวัน, `90d` รายสัปดาห์เริ่มวันจันทร์, `all` รายเดือน) ช่วงที่ไม่มีข้อมูลแสดงเป็น 0
5. Heatmap วัน (จ.–อา.) × ช่วงละ 2 ชั่วโมง นับตามเวลาเริ่มกิจกรรม และรายการสรุปแยกตามหมวดหมู่ วางคู่กันบนจอใหญ่
   - รายการหมวดหมู่แสดงจำนวนกิจกรรมพร้อมแท่ง และบรรทัดรอง "เติมที่นั่ง · มาตามนัด · ★ คะแนน (จำนวนรีวิว)"
6. หมายเหตุวิธีนับท้ายหน้า

ทุกการ์ดมีบรรทัด "ข้อสังเกต" ที่คำนวณจากข้อมูลจริง กราฟแนวโน้มและ heatmap มีปุ่ม "ดูข้อมูลเป็นตาราง" และขึ้น tooltip เมื่อชี้

## สเปกกราฟ (ตามสกิล dataviz)

ตรวจสีด้วย `validate_palette.js` แล้วบนพื้นการ์ดสีขาว ประกาศเป็น CSS custom properties ในหน้า:

| ใช้กับ | สี |
|---|---|
| แท่งข้อมูล (แนวโน้ม หมวดหมู่) | `#2a78d6` (contrast 4.42:1) |
| Heatmap 5 ระดับ | `#86b6ef`, `#5598e7`, `#2a78d6`, `#1c5cab`, `#0d366b` (ผ่าน `--ordinal`) |
| ช่องที่เป็น 0 | `#f5f5f3` (canvas) |

- **แท่ง:** หนาไม่เกิน 24px ปลายมุม 4px เว้นระยะ 2px
- **ป้ายตัวเลข:** ใส่เฉพาะค่าสูงสุดและแท่งล่าสุด
- **ระดับสี heatmap:** `ceil(v × 5 / max)` คำนวณด้วยจำนวนเต็ม และมี legend บอกช่วงค่า
- **Tooltip:** ใส่ข้อความด้วย `textContent` เท่านั้น ทุกค่าใน tooltip ดูได้จากตารางเทียบเท่า
- **ตัวเลข KPI:** ไม่ใช้ `tabular-nums`

## ไฟล์ CSV (`admin.insights.export`)

- **ชื่อไฟล์:** `unimate-stats-{range}-{YYYY-MM-DD}.csv`
- **รูปแบบ:** UTF-8 มี BOM คั่นด้วยจุลภาค
- **ตอนในไฟล์ตามลำดับ:**
  - ข้อมูลช่วงเวลา
  - สรุปตัวเลข (ตัวชี้วัด / ค่า / หน่วย)
  - แยกตามหมวดหมู่
  - จำนวนกิจกรรมตามช่วง (มีคอลัมน์วันที่แบบ `YYYY-MM-DD` ให้เรียงหรือทำกราฟต่อได้)
  - ตารางวัน × เวลา
- **ตัวเลขเป็นค่าดิบ:** เปอร์เซ็นต์เป็นทศนิยม 1 ตำแหน่งโดยไม่มีเครื่องหมาย % และค่าที่ไม่มีข้อมูลเป็นช่องว่าง
- **กันสูตร Excel:** ข้อความที่ขึ้นต้นด้วย `= + - @` ถูกใส่ `'` นำหน้า กันการตีความเป็นสูตร (CSV injection) เช่น ชื่อหมวดหมู่ที่ผู้ดูแลตั้งเอง

## ข้อมูลตัวอย่าง (`AdminInsightsDemoSeeder`)

- **วิธีรัน:** `php artisan db:seed --class=AdminInsightsDemoSeeder` ต้องรัน `UserSeeder` และ `CategorySeeder` มาก่อน
- **ไม่อยู่ใน `DatabaseSeeder`:** DB ของเพื่อนจึงไม่มีข้อมูลนี้ถ้าไม่รันเอง
- **รันซ้ำได้:** ลบเฉพาะข้อมูลของตัวเองก่อนสร้างใหม่ (ผู้ใช้ `insights.NN@unimate.ac.th` และทุกอย่างที่ผูกกับผู้ใช้เหล่านี้) และใช้ `mt_srand` ค่าคงที่
- **ผู้ใช้:** นักศึกษา 90 คน สมัครกระจายตลอด 12 เดือน
  - ประมาณ 1 ใน 3 เลิกใช้หลังสมัคร 20–60 วัน
  - ขาประจำถูกสุ่มให้ส่งคำขอบ่อยกว่า "ผู้ใช้ที่มีส่วนร่วม" จึงอยู่ราว 70–80% ไม่ใช่เกือบ 100%
- **กิจกรรม:** ประมาณ 195 อัน (ย้อนหลัง 9 เดือนและอีก 3 สัปดาห์ข้างหน้า) เวลาสมจริงตามหมวด ยกเลิกประมาณ 6%
- **คำขอ การเช็กชื่อ และรีวิว:** อนุมัติได้ไม่เกิน capacity เช็กชื่อ present ประมาณ 82% / absent 10% / ยังไม่เช็ก 8% และประมาณ 45% ของผู้ที่มาให้รีวิว
- **สำรอง DB:** ไฟล์ DB ในเครื่องก่อนใส่ข้อมูลตัวอย่างอยู่ที่ `database/database.before-insights-demo.sqlite`

## การทดสอบ (9 เทสต์ใน `AdminInsightsTest.php`)

- **สิทธิ์:** ทั้งหน้าเว็บและ CSV guest ถูกส่งไป login นักศึกษาได้ 403 และแอดมินได้ 200
- **เมนู:** เมนูแอดมินมีลิงก์ไปหน้านี้
- **DB ว่าง:** ทุกช่วงเวลาแสดง empty state ได้ ดาวน์โหลด CSV ได้ และไม่หารด้วย 0
- **ความถูกต้องของตัวเลข:** ตรวจ KPI และหมวดหมู่กับข้อมูลที่รู้คำตอบล่วงหน้า รวมกรณีแอดมินจัดกิจกรรมแล้วยกเลิก
- **ช่วงเวลา:** ตัวกรองนับถูก และค่า range ที่ผิดใช้ `90d`
- **Heatmap:** กิจกรรมวันศุกร์ 17:30 อยู่ในช่องศุกร์ × 16–18 และข้อสังเกตชี้ช่องนี้
- **CSV:** มี BOM ชื่อไฟล์ถูกต้อง ค่าตรงกับข้อมูล และกัน CSV injection
- **Escape:** ชื่อหมวดที่มี `<script>` ถูก escape
