# แผน: รีวิวผู้ใช้ (แยกจากรีวิวกิจกรรม)

สถานะเดิม (14 ต.ค. 2026): มีแค่รีวิวกิจกรรม (ตาราง `reviews`) คะแนนในโปรไฟล์คำนวณจากรีวิวกิจกรรมที่คนนั้นจัด
ผู้เข้าร่วมไม่มีคะแนน และผู้จัดรีวิวอะไรไม่ได้เลย

เป้าหมาย: เพิ่ม "รีวิวคน" แยกจาก "รีวิวกิจกรรม" โดยรีวิวกิจกรรมเดิมไม่เปลี่ยน

## กติกา

- **กลุ่มคนที่ไปจริง** = ผู้จัด + ผู้เข้าร่วมที่ status=approved และ attendance=present
- ทุกคนในกลุ่มนี้รีวิวคนอื่นในกลุ่มได้ (ผู้จัด↔ผู้เข้าร่วม, ผู้เข้าร่วม↔ผู้เข้าร่วม) แต่รีวิวตัวเองไม่ได้
- รีวิวได้เมื่อกิจกรรมจบแล้ว ไม่ถูกยกเลิก และไม่ถูกซ่อน
- คนที่ขาดหรือไม่ได้รับอนุมัติ รีวิวไม่ได้และถูกรีวิวไม่ได้
- 1 รีวิวต่อ (กิจกรรม, ผู้รีวิว, ผู้ถูกรีวิว) ดาว 1-5 ความเห็นไม่บังคับ (สูงสุด 1000 ตัวอักษร)
- แก้ไขและลบรีวิวของตัวเองได้ คนอื่นรายงานได้ Admin ลบได้พร้อมเหตุผล (เหมือนรีวิวกิจกรรม)
- หากแก้การเช็กชื่อภายหลัง เจ้าของยังจัดการรีวิวเดิมได้ แต่สิทธิ์ส่งรีวิวใหม่ใช้รายชื่อผู้มาร่วมจริงปัจจุบัน
- ทุกเงื่อนไขต้องตรวจที่เซิร์ฟเวอร์ ไม่ใช่แค่ซ่อนปุ่ม

## ข้อมูล

- migration ใหม่ ตาราง `user_reviews`
  - คอลัมน์: `id`, `activity_id` (FK cascade), `reviewer_id` (FK users cascade), `reviewee_id` (FK users cascade),
    `reviewee_role` (`host`|`participant` บันทึกตอนสร้าง), `rating` (tinyint), `comment` (text null), timestamps
  - unique (`activity_id`, `reviewer_id`, `reviewee_id`) และ index (`reviewee_id`, `reviewee_role`)
- โมเดล `UserReview` + relation บน User (`reviewsWritten`, `reviewsReceived`) และ Activity (`userReviews`)
- ฟังก์ชันกลาง เช่น `Activity::attendees()` (ผู้จัด + คนที่มา) และ `Activity::userReviewBlockReason(User $reviewer, User $reviewee): ?string`
  ใช้ร่วมกันทั้ง controller และ view (แบบเดียวกับ `reviewBlockReason`)
- ตาราง `reviews` เดิมไม่แตะ

## หน้าเว็บ

1. **`GET /activities/{activity}/people`** (route `activities.people`) หน้า "รีวิวเพื่อนร่วมกิจกรรม"
   - เปิดได้เฉพาะคนในกลุ่มที่ไปจริง เจ้าของรีวิวเดิม และ Admin (ดูอย่างเดียวเมื่อไม่ได้ร่วม) คนอื่นได้ 403
   - รายชื่อคนที่ไปจริง ยกเว้นตัวเอง แต่ละคนมีรูป ชื่อ (ลิงก์โปรไฟล์) และป้าย "ผู้จัด"/"ผู้เข้าร่วม"
   - ถ้ายังไม่ได้รีวิว: ดาว + ความเห็น + ปุ่ม ถ้ารีวิวแล้ว: แสดงรีวิวของฉัน และให้แก้ไขหรือลบได้
   - error ของแต่ละฟอร์มต้องเปิดเฉพาะฟอร์มของคนนั้น (ใช้ hidden id แบบฟอร์มรายงานรีวิว)
   - route `POST /activities/{activity}/people/{user}/review`, `PATCH|DELETE /activities/{activity}/user-reviews/{userReview}` (scopeBindings)
2. **หน้ากิจกรรม** (`activities/show`): ถ้าผู้ใช้อยู่ในกลุ่มที่ไปจริงและกิจกรรมจบแล้ว ให้มีปุ่ม
   "รีวิวเพื่อนร่วมกิจกรรม" พร้อมจำนวนคนที่ยังไม่ได้รีวิว ผู้จัดเห็นปุ่มนี้ด้วย
3. **นัดของฉัน**: ปุ่ม "ให้คะแนน" ต้องนับงานรีวิวที่ค้างทั้งรีวิวกิจกรรมและรีวิวคน
   ทั้งในกิจกรรมที่เข้าร่วมและกิจกรรมที่ตัวเองจัด ลิงก์ไปที่ที่เหมาะสม
   (ถ้ายังไม่ได้รีวิวกิจกรรม ไปที่ `#reviews` ไม่อย่างนั้นไปหน้า people)
4. **โปรไฟล์** (`users/show`, `UserProfileController`):
   - ตัวเลขสรุป: คะแนนในฐานะผู้จัด, คะแนนในฐานะผู้เข้าร่วม (เฉลี่ยจาก user_reviews ตาม reviewee_role ไม่นับกิจกรรมที่ถูกซ่อน)
     และมาตามนัด X/Y ครั้ง (Y = approved ในกิจกรรมที่จบแล้วและเช็กชื่อแล้ว, X = present)
   - "รีวิวที่ได้รับ" แยก 2 แท็บ: ในฐานะผู้จัด และในฐานะผู้เข้าร่วม (แท็บใช้ query string ไม่ต้องใช้ JS)
     แต่ละรีวิวแสดงผู้รีวิว (ลิงก์) ดาว ความเห็น ชื่อกิจกรรม (ลิงก์) วันที่ และปุ่มรายงาน
   - เลิกใช้รีวิวกิจกรรมเป็นคะแนนผู้จัดในโปรไฟล์ (คะแนนกิจกรรมยังแสดงที่การ์ดกิจกรรม)
5. **หน้าจัดการคำขอ** (`activities/requests`): ข้างชื่อผู้ขอแสดงคะแนนในฐานะผู้เข้าร่วม (ดาว + จำนวนรีวิว) และมาตามนัด X/Y
   คำนวณแบบรวม query ไม่ query ทีละคน
6. **แจ้งเตือน**: ผู้ถูกรีวิวได้รับ "{ชื่อ} ให้คะแนนคุณ N ดาว จากกิจกรรม '{ชื่อกิจกรรม}'" ใช้ kind `review`
   และลิงก์ relative ไปโปรไฟล์ของตัวเอง ใช้ `route(..., false)`
7. **รายงานและ Admin**:
   - รายงานรีวิวคนได้: `reports.target_type = 'user_review'` (string(20) พอ ไม่ต้องแก้ migration เดิม)
   - หน้า `/admin/reports` แสดงผู้รีวิว ผู้ถูกรีวิว ดาว ความเห็น และกิจกรรม Admin เลือก "ลบรีวิว" หรือ "ยกรายงาน"
   - Admin ลบรีวิวคนพร้อมเหตุผลได้ บันทึก moderation_logs action `delete_user_review` แจ้งผู้เขียน และปิดรายงานที่ค้างของรีวิวนั้น
     ใช้แนวเดียวกับ `Review::deleteByAdmin()` ให้มาก
   - ปรับ label ใน `Report`/`ModerationLog` ให้รองรับ `user_review`

## ข้อมูลเดโม (`PresentationDemoSeeder` + `docs/demo-guide-th.md`)

- เพิ่มรีวิวคนในกิจกรรมที่จบแล้ว: ผู้จัดรีวิวผู้เข้าร่วม, ผู้เข้าร่วมรีวิวผู้จัด, ผู้เข้าร่วมรีวิวกันเอง ให้คะแนนในโปรไฟล์ดูสมจริง
- `student@` ต้องมีงานรีวิวคนค้างให้กดสด:
  - ในฐานะผู้เข้าร่วม: กิจกรรม "เดินป่า…"
  - ในฐานะผู้จัด: กิจกรรมที่จบและเช็กชื่อแล้ว เช่น "บาสเย็นวันพุธ"
- มีรีวิวคนที่ไม่สุภาพ 1 อันถูกรายงานรอตรวจ (รายงานรอตรวจจะกลายเป็น 5 ให้แก้เทสต์ seeder ตาม)
- `AdminInsightsDemoSeeder` ไม่ต้องแก้
- อัปเดตบทเดโมในคู่มือ

## ข้อห้ามและมาตรฐาน

- ไม่เปลี่ยนพฤติกรรมรีวิวกิจกรรมเดิม และเทสต์เดิมต้องผ่าน
- ไม่เปลี่ยนข้อความที่เทสต์ตรวจ ("ส่งรีวิว" ต้องมีเฉพาะในฟอร์มรีวิวกิจกรรมใหม่ ปุ่มรีวิวคนให้ใช้ "ส่งรีวิวผู้ใช้" หรือคำอื่น)
- UI ใช้คลาสธีมและคอมโพเนนต์ `x-ui.*` ตาม `docs/ui-design-th.md` และใช้ `x-ui.user-link` กับชื่อคน
  ครอบข้อความผู้ใช้ด้วย `break-anywhere` และไม่ใส่ข้อมูลผู้ใช้ลงใน JavaScript ตรง ๆ (ใช้ `Js::from`)
- เทสต์ใหม่ `tests/Feature/UserReviewTest.php` ใช้ helper ขึ้นต้น `ur`
