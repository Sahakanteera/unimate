## หลังดึงโค้ดลงเครื่องของแต่ละคน

ใช้ environment และ dependencies ของโปรเจกต์ตามเดิม แล้วรัน:

```sh
php artisan migrate
php artisan db:seed --class=CategorySeeder
php artisan test tests/Feature/ActivitiesTest.php
```

ไม่ต้องใช้ `migrate:fresh` เพราะจะล้างข้อมูลเดิม การ migrate บนเครื่องผู้พัฒนาไม่ได้ทำให้ฐานข้อมูลบนเครื่องเพื่อนมีตารางใหม่อัตโนมัติ แต่ละคนต้องรันคำสั่งเอง

ล็อกอินแล้วเปิด `/activities` ส่วน Admin เปิด `/admin/categories` ระบบนี้ใช้ layout Blade เดิมของโปรเจกต์

## จุดเชื่อมต่อสำหรับเพื่อนในทีม

- Model หลัก: `App\Models\Activity` และ `App\Models\Category`
- `activities.user_id` คือเจ้าของโพสต์; `activity->user` คือผู้ประกาศ
- `activities.category_id` คือหมวดหมู่; `activity->category` คือหมวดหมู่ที่สัมพันธ์กัน
- `capacity` คือจำนวนที่รับเพิ่ม **ไม่รวมผู้ประกาศ** ยังไม่มีข้อมูลยอดผู้เข้าร่วมจริง
- สถานะที่มี: `published` และ `cancelled` หน้าเริ่มต้นแสดง published; เลือกดู cancelled หรือ all ได้
- `published` หมายถึงประกาศแล้ว ไม่ใช่การรับรองว่ายังมีที่ว่างหรือยังไม่หมดเวลา
- เวลาใช้ `Asia/Bangkok` ผ่าน `config/app.php` ทั้งแอป การตั้งค่านี้เปลี่ยนจาก UTC แต่ไม่ได้แปลงข้อมูลเวลาเก่าย้อนหลัง
- ลิงก์รายละเอียดใช้ `route('activities.show', $activity)`
- สิทธิ์แก้ไขใช้ `ActivityPolicy::update` สิทธิ์ยกเลิกใช้ `ActivityPolicy::cancel` ไม่มีสิทธิ์พิเศษของ Admin สำหรับโพสต์คนอื่น
- โพสต์ที่ยกเลิกยังอ่านได้ แต่เข้าแก้ไขหรือส่งแก้ไขไม่ได้ (409)
- การแก้ไขต้องระบุเวลาเริ่มในอนาคตตามกฎปัจจุบัน

## งานที่ยังไม่ได้ทำในส่วนนี้

- สมัคร/ออกจากกิจกรรม รายชื่อและจำนวนผู้เข้าร่วมจริง
- การอนุมัติ/ปฏิเสธผู้เข้าร่วม และการป้องกันจำนวนคนเกินความจุ
- หน้านัดของฉัน (เมนูเดิมยังเป็น placeholder)
- แชต แจ้งเตือน เตือนก่อนเริ่มกิจกรรม และรีวิว
- อัปโหลดรูปกิจกรรม และแผนที่พิกัด

เมื่อเชื่อมระบบเข้าร่วม ให้สร้างข้อมูลผู้เข้าร่วมแยกโดยอ้างอิง `activity_id` และ `user_id` และตรวจสถานะยกเลิก เวลาเริ่ม รวมถึงจำนวนที่ว่างที่เซิร์ฟเวอร์ก่อนบันทึก การนับและบันทึกผู้เข้าร่วมควรอยู่ใน transaction เพื่อรองรับคนสมัครพร้อมกัน ทั้งหมดนี้เป็นแนวทางส่งต่อ ยังไม่ได้ implement ในงานนี้

## ผลการตรวจสอบและข้อจำกัด

- ชุดทดสอบกิจกรรม: ผ่าน 14 กรณี รวม 88 assertions
- ครอบคลุมสร้าง → ค้นหา → ดูรายละเอียด → แก้ไข → ยกเลิก, กฎข้อมูล, สิทธิ์เจ้าของ, Admin, บัญชีถูกระงับ และหมวดหมู่
- Laravel Pint ผ่าน และ Blade templates compile ได้
- PHPStan หลังเพิ่ม memory limit ไม่พบข้อผิดพลาดในไฟล์ PHP ที่เพิ่มสำหรับระบบกิจกรรม แต่ยังพบในไฟล์ระบบสมาชิกเดิม
- ชุดทดสอบทั้งโปรเจกต์ยังไม่ผ่านทั้งหมด: มีการอ้างอิง route เดิม เช่น dashboard / security.edit / register.store / login.store, ปัญหา two-factor และ Vite manifest ของหน้า starter kit ไม่ได้แก้ระบบเหล่านี้ในงานกิจกรรม
- ยังไม่ได้ตรวจหน้าจอด้วยเบราว์เซอร์จริง ผลการตรวจหน้าจอปัจจุบันเป็นการ render ผ่าน feature tests และ compile Blade
