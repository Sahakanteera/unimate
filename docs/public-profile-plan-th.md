# แผน: โปรไฟล์สาธารณะ + ปรับระบบรีวิวกิจกรรม (ส่วนที่ 5)

สถานะเดิม (14 ต.ค. 2026, branch `kim`)
- รีวิวมีแค่ "รีวิวกิจกรรม" ตาราง `reviews` (activity_id, user_id, rating 1-5, comment) ไม่มีรีวิวผู้ใช้โดยตรง
- `/profile` แก้โปรไฟล์ตัวเองได้อย่างเดียว ไม่มีหน้าดูโปรไฟล์คนอื่น ชื่อผู้ใช้ทุกที่กดไม่ได้
- รีวิวที่ส่งแล้วแก้หรือลบไม่ได้ ผู้จัดไม่รู้ว่ามีรีวิวใหม่ และ Admin ลบรีวิวที่ไม่เหมาะสมไม่ได้

หลักการ: MVP ไม่เพิ่มตาราง ไม่มี migration ใหม่ ใช้ข้อมูลที่มีอยู่

## A. หน้าโปรไฟล์สาธารณะ `/users/{user}` (route `users.show`)

- อยู่ในกลุ่ม middleware `auth`, `active` ใช้ Controller ใหม่ `UserProfileController@show`
- ผู้ใช้ที่ถูกระงับ: คนทั่วไปเห็นเป็น 404 ส่วน Admin เห็นได้
- **ไม่แสดง** อีเมลและรหัสนักศึกษาให้คนอื่นเห็น (ข้อมูลส่วนตัว)
- ส่วนหัว: รูปหรืออักษรย่อ ชื่อ บทบาท bio วันที่สมัคร ถ้าเป็นโปรไฟล์ตัวเองมีปุ่ม "แก้ไขโปรไฟล์"
- ตัวเลขสรุป
  - กิจกรรมที่จัด: ไม่นับกิจกรรมที่ยกเลิกหรือถูกซ่อน
  - เข้าร่วมแล้ว: approved + attendance=present + กิจกรรมจบแล้ว (นิยามเดียวกับสิทธิ์รีวิว)
  - คะแนนผู้จัด: ค่าเฉลี่ยคะแนนรีวิวของกิจกรรมที่คนนี้จัด ไม่นับกิจกรรมที่ถูกซ่อน พร้อมจำนวนรีวิว
    ป้ายต้องเขียนชัดว่าเป็น "คะแนนจากการจัดกิจกรรม"
- ประวัติ
  - กิจกรรมที่จัด: ใช้ `x-activity-card` ต้อง eager load ตามที่คอมโพเนนต์ต้องการ (withCount/withAvg)
    ซ่อนกิจกรรมที่ถูกซ่อน เว้นแต่ผู้ดูเป็นเจ้าของหรือ Admin ให้แบ่งหน้าแยก pageName
  - กิจกรรมที่เข้าร่วมแล้ว: ตามนิยามข้างบน ไม่รวมกิจกรรมที่ถูกซ่อน และแบ่งหน้าแยก
  - รีวิวที่ได้รับ: รีวิวล่าสุดของกิจกรรมที่คนนี้จัด แสดงผู้รีวิว (กดไปโปรไฟล์ได้) ดาว ความเห็น และชื่อกิจกรรม (กดไปหน้ากิจกรรมได้)
- Empty state ทุกส่วนต้องมีข้อความ

## B. ทำให้ชื่อหรือรูปผู้ใช้กดไปโปรไฟล์ได้

- หน้ากิจกรรม: บรรทัด "ประกาศโดย" การ์ดผู้จัด รายชื่อสมาชิก และผู้รีวิว
- หน้าคำขอเข้าร่วม (`activities/requests`): ผู้จัดกดดูโปรไฟล์ผู้ขอเข้าร่วมก่อนอนุมัติได้
- `my-activities`: "โดย {ชื่อ}"
- Admin: หน้ารายชื่อผู้ใช้และหน้ารายงาน (เป้าหมายที่เป็นผู้ใช้)
- เมนูผู้ใช้ใน nav: เพิ่ม "โปรไฟล์ของฉัน" และในหน้า `/profile` เพิ่มลิงก์ "ดูโปรไฟล์ที่คนอื่นเห็น"

## C. ปรับระบบรีวิวกิจกรรม

1. แก้ไขรีวิวของตัวเอง: `PATCH /activities/{activity}/reviews/{review}` ได้เฉพาะเจ้าของรีวิว ตรวจสิทธิ์ที่เซิร์ฟเวอร์
   ใช้กฎ validate เดียวกับตอนสร้าง ถ้ากิจกรรมถูกซ่อน ห้ามแก้
2. ลบรีวิวของตัวเอง: `DELETE` route เดียวกัน มี confirm
3. แจ้งผู้จัดเมื่อมีรีวิวใหม่: ใช้ `ActivityNotification` เดิม เช่น "มีรีวิวใหม่ 4 ดาว ในกิจกรรม '...'"
4. Admin ลบรีวิวที่ไม่เหมาะสม: ต้องใส่เหตุผล บันทึกลง `moderation_logs`
   (action `delete_review`, target_type `review`) แจ้งผู้เขียนรีวิว ปุ่มอยู่ในหน้ากิจกรรม เห็นเฉพาะ Admin
5. หน้ากิจกรรม: รีวิวของฉันอยู่บนสุดพร้อมป้าย "รีวิวของคุณ" และปุ่มแก้ไขหรือลบ
   ถ้ามีรีวิวแล้วให้แสดงฟอร์มแก้ไข แทนข้อความ "คุณรีวิวกิจกรรมนี้ไปแล้ว"
6. `my-activities`: กิจกรรมที่จบแล้ว ผู้ใช้เข้าร่วมจริง และยังไม่รีวิว ให้มีปุ่ม "ให้คะแนน" ลิงก์ไป `#reviews`

## ข้อห้าม

- ห้ามเปลี่ยนข้อความที่เทสต์เดิมตรวจ: "(N รีวิว)", "จาก N รีวิว", "ส่งรีวิว" (มีเฉพาะในฟอร์มรีวิวใหม่), "แก้ไขกิจกรรม", "คุณรีวิวกิจกรรมนี้ไปแล้ว" (error ตอน POST ซ้ำ)
  ปุ่มในฟอร์มแก้ไขรีวิวต้องใช้คำอื่น เช่น "บันทึกการแก้ไข"
- UI ใช้คลาสจาก `partials/theme.blade.php` และคอมโพเนนต์ `x-ui.*` ตาม `docs/ui-design-th.md`
  ครอบข้อความที่ผู้ใช้กรอกด้วย `break-anywhere` และใส่ `min-w-0` ให้ลูกของ grid
- ไม่ commit และไม่ push
